# Defenses Against Indirect Prompt Injection

Indirect prompt injection happens when an LLM agent reads external content (an email, a web page, a tool result) that contains hidden instructions, and then follows those instructions instead of the user's. This project implements prompt-level defenses against that attack and measures how well they work on three established benchmarks.

Built for the *Security & Privacy of Machine Learning* course at Radboud University.

---

## Defenses

All defenses are based on **spotlighting** ([Hines et al., 2024](https://arxiv.org/abs/2403.14720)): the untrusted content is transformed so the model can tell it apart from the user's instruction, and the system prompt explains the convention and tells the model to treat that content as data only.

| Defense | What it does to untrusted content | Example |
| --- | --- | --- |
| **Delimiting** | Wraps it in start and end markers | `<<<UNTRUSTED_DATA_START>>> … <<<UNTRUSTED_DATA_END>>>` |
| **Datamarking** | Puts a marker character between every word | `Ignore^previous^instructions` |
| **Encoding** | Encodes the whole text | Base64 |

Each defense also has a **randomized** variant, where the parameters are picked at random for every sample. An attacker who knows the defense then cannot predict the exact format to imitate or escape.

| Randomized variant | Pool of choices |
| --- | --- |
| Delimiting | 100 delimiter pairs (10 role words × 10 styles, e.g. `<data>…</data>`, `[BEGIN_INPUT]…[END_INPUT]`, `<\|begin_context\|>…`) |
| Datamarking | 176 markers (single characters, pairs and triples from `@ # $ % & * ~ + = ! ^`) |
| Encoding | 9 schemes: Base64, Base32, ROT13, ROT47, hex, octal, binary, Unicode escapes, Morse |

The shared implementation is in [`defenses/`](defenses). [`defenses_demo.ipynb`](defenses/defenses_demo.ipynb) shows each defense applied to an example.

## Benchmarks

| Benchmark | Scenario | What we changed |
| --- | --- | --- |
| [**BIPIA**](https://github.com/microsoft/BIPIA) | LLM answers questions about external content (e.g. emails) that contains an injected instruction | New async runner `benchmark_defense.py` that first finds attacks that succeed without a defense, then re-runs only those against all 7 defense conditions. An LLM judge decides if the attack succeeded. vLLM removed so it runs against a remote API. |
| [**InjecAgent**](https://github.com/uiuc-kang-lab/InjecAgent) | Tool-using ReAct agent receives a tool response with an injected instruction | Tool responses are passed through a defense before the agent sees them. Works with any OpenAI-compatible endpoint. |
| [**AgentDojo**](https://github.com/ethz-spylab/agentdojo) | Full agent environments (workspace, Slack, travel, banking) with realistic tasks and attacks | Added `delimiting`, `datamarking` and `encoding` defenses to the agent pipeline, plus a `LOCAL` provider for OpenAI-compatible model servers. |

### Models

All three benchmarks were run on models hosted locally at Radboud University (e.g. `gemma4:31b`, `qwen3.6:35b`). Because of API budget limits, only BIPIA was also run against DeepSeek.

## Getting started

```bash
git clone --recurse-submodules https://github.com/beatrisebertule/indirect-promt-injection-defenses.git
cd indirect-promt-injection-defenses
uv pip install -e .
```

If you already cloned without submodules, run `git submodule update --init --recursive`.

Every benchmark talks to an OpenAI-compatible API, configured with these environment variables:

```bash
export OPENAI_BASE_URL="https://your-endpoint/v1"
export OPENAI_API_KEY="your-key"
```

### BIPIA

```bash
cd bipia_benchmark
cp compose.example.yml compose.yml   # then set your API key, TARGET_MODEL and JUDGE_MODEL
docker compose up --build
```

Or run the script directly:

```bash
python benchmark_defense.py --dataset email --limit 50 --mode all
```

| Option | Description |
| --- | --- |
| `--dataset` | BIPIA dataset, e.g. `email` |
| `--limit` | Number of samples to scan (random, fixed seed); `0` for the full benchmark |
| `--mode` | `baseline` (find successful attacks only), `defenses` (test defenses only) or `all` |
| `--concurrency` | Maximum parallel API requests |
| `--mock` | Use fake model responses, for testing without API cost |

Results go to `experiment_output/`. `comparison_summary.json` gives the attack success rate (ASR) for each defense. `judge_config.yaml` is generated by BIPIA and can be ignored.

### InjecAgent

```bash
cd InjecAgent
pip install -r requirements.txt
export PYTHONPATH=.
python src/evaluate_prompted_agent.py \
  --model_type GPT --model_name qwen3.6:35b \
  --setting base --prompt_type InjecAgent
```

The defense applied to tool responses is set in `src/evaluate_prompted_agent.py` (randomized datamarking by default). See [`InjecAgent/README.md`](InjecAgent/README.md) for all options.

### AgentDojo

```bash
cd agentdojo_benchmark
docker build -t agentdojo-benchmark .

docker run -e OPENAI_API_KEY="your-key" -e OPENAI_BASE_URL="https://your-endpoint/v1" \
  agentdojo-benchmark --model LOCAL --model-id gemma4:31b \
  -s workspace --attack tool_knowledge --defense delimiting
```

- Leave out `--attack` to measure normal task performance (utility).
- Leave out `--defense` to get the no-defense baseline.
- `--defense` accepts `delimiting`, `datamarking`, `encoding`, plus AgentDojo's built-in defenses.
- `-s` picks the task suite: `workspace`, `slack`, `travel` or `banking`.
- Add `-ut user_task_0` to run a single task.

See [`agentdojo_benchmark/README.md`](agentdojo_benchmark/README.md) for running without Docker.
